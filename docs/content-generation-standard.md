# 内容生成标准

本文件是 study-ai-mvp 后续所有课程内容生成与章节增强任务的全局标准。处理任何新课程、sample、full 或单章增强前，内容生成模型必须先阅读并遵守本文件；如果用户没有特别说明，应优先遵守本文件。

## 1. 项目内容定位

study-ai-mvp 的课程内容主要服务期末复习，同时兼顾日常学习。

生成目标不是单纯完整搬运 PPT，也不是只做课程提纲，而是：

- 完整吸收原始资料；
- 按期末复习价值分层展示；
- 把核心公式、核心机制、典型计算题、关键判断逻辑放在主学习路径；
- 把新闻链接、市场截图、机构实践、延伸阅读放在辅助或拓展位置；
- 用 visualBlocks 重建资料中的公式、表格、流程、案例、例题、现金流图、收益图和判断路径。

内容生成时必须避免两个极端：

- 不能把 50 页 PPT 压成几条提纲；
- 也不能把 PPT 中所有内容等权展示。

## 2. P0/P1/P2/P3 分层标准

每章增强前必须先做复习价值分层，再写入 framework JSON。

### P0：必须掌握

学生如果不会，可能直接影响期末考试答题。

包括：

- 核心定义；
- 核心公式；
- 核心机制；
- 典型计算题；
- 关键判断逻辑；
- 老师知识目标、掌握要求、回顾页反复强调的内容；
- 能直接转化为选择题、判断题、计算题、简答题的内容。

展示要求：

- 必须进入主学习模块；
- 公式、例题、图表要靠近对应知识点；
- 不要折叠或弱化；
- 优先生成 formula_card、example_box、process_flow、data_table、comparison_table 等结构化内容。

### P1：重点理解

服务 P0 的重要解释和机制。

包括：

- 核心公式背后的机制解释；
- 重要对比；
- 重要图示；
- 常见变形；
- 关键影响因素；
- 与 P0 紧密相关的制度逻辑、市场逻辑或风险逻辑。

展示要求：

- 进入主学习模块；
- 放在 P0 内容之后或与 P0 自然结合；
- 可以用 comparison_table、chart_explanation、process_flow、curve_chart、case_card 等表达。

### P2：辅助复习

有助于理解课程，但考试价值低于 P0/P1。

包括：

- 背景说明；
- 制度细节；
- 市场分类；
- 课堂补充；
- 与核心考点相关但不是主线的材料；
- 低频应用场景。

展示要求：

- 放在对应模块后部；
- 如果前端支持折叠，作为补充理解；
- 不要占用主视觉；
- 不要生成大量醒目的 visualBlocks。

### P3：拓展材料

与课程相关，但主要用于拓展、市场观察或课外阅读。

包括：

- 新闻链接；
- 研究报告链接；
- 机构实践截图；
- 数据库介绍；
- 市场延伸阅读；
- PPT 目录中出现但正文没有系统展开的内容。

展示要求：

- 放入拓展材料或对应模块末尾；
- 不进入主学习路径；
- 不为 P3 内容硬造复杂 visualBlocks；
- 不把截图、链接和核心公式例题等权展示。

## 3. 例题 / 应用题 / 推导链识别规则

如果 PPT 中出现以下信号，必须优先判断是否应生成 example_box：

- 例；
- 应用；
- 问；
- 答；
- 思考；
- 求解得；
- 根据下表；
- 如何通过；
- 公允价值；
- 按照一价原则；
- 计算；
- 判断。

如果连续多页出现以下结构，也必须合并为一个完整 example_box：

题目 → 表格/条件 → 设变量/列方程 → 解答/结论。

必须特别注意：

- 完整应用题不能只处理成 data_table；
- 连续页推导不能只抽其中一页的表格；
- 公式卡不能替代例题步骤；
- chart_explanation 不能替代计算题解法；
- 如果表格服务于题目，它是 example_box 的已知条件，而不是例题本身。

## 4. Office 数学对象检查规则

不能只依赖普通文本抽取结果。

如果普通文本中公式、权重、结果缺失，但 PPT 页面明显是计算题或推导题，必须进一步检查：

- Office 数学对象；
- 表格对象；
- PPT 中的公式对象；
- 页面渲染截图；
- 相邻页内容；
- chunks / slide inventory 中的信息。

如果数学对象中能确认公式、权重、结果，应写入 example_box。

如果仍无法确认：

- 保留题目结构；
- 保留解题路径；
- 保留能确认的方程或计算逻辑；
- 对无法确认的具体数字标注“需人工核对”；
- 不伪造数字。

第 4 章“用 A、B、C 附息债券复制 1 年期零息债券”的经验必须作为反例记住：普通文本抽取漏掉了 Office 数学对象中的权重和公允价值，不能因此把完整应用题降级为普通表格。

## 5. LaTeX / 数学对象写入 JSON 规则

所有写入 framework JSON 的数学变量、公式和计算式，都必须能被 MathText / KaTeX 正确识别。

必须遵守：

- 普通文本中的数学变量必须使用 MathText 可识别格式，例如 `\(N_A\)`、`\(F_0\)`、`\(S_T\)`。
- JSON 字符串中的反斜杠必须正确转义。文件中应能看到 `\\(N_A\\)`、`\\times`、`\\approx` 这类写法。
- 禁止出现 `imes`、裸 `approx`、`(N_A)`、`(3N_A+5N_B+10N_C=100)` 这类损坏公式或伪公式。
- 如果公式来自 Office 数学对象，必须转换成合法 LaTeX 后再写入 JSON。
- 数学公式应尽量放在 `formula` / `formulaLatex` 字段，或放在 MathText 可识别的文本中。
- 不要把公式混入普通中文括号里；需要行内公式时使用 `\( ... \)`。
- `\times`、`\approx`、`\leq`、`\geq`、`\max`、`\min` 等命令必须保留反斜杠。
- 写入后必须搜索检查 `imes`、`approx`、`(N_`、`N_A)`、`N_B)`、`N_C)` 等常见损坏痕迹。

示例：

- 错误：`(N_A)`
- 正确：`\(N_A\)`
- 错误：`P=-57.75 imes98.68+56.65 imes104.34-1 imes113.89approx98.2`
- 正确：`\(P=-57.75\times 98.68+56.65\times 104.34-1\times 113.89\approx 98.2\)`

## 6. 数值不确定时的处理规则

错误做法：

- 因为权重或最终数值不确定，就删除例题结构；
- 只保留表格说明；
- 把高价值例题降为 P2/P3；
- 编造 PPT 中没有的数字。

正确做法：

- 保留题目条件；
- 保留问题或判断任务；
- 保留解题思路；
- 保留方程或计算路径；
- 能确认的数字写出；
- 不能确认的数字标注“需人工核对”；
- 不伪造；
- 不把例题降级为 P2/P3。

数值不确定只影响“具体结果是否写入”，不影响“例题结构是否保留”。

## 7. 表格与 example_box 的关系

如果表格只是分类或对比，可以使用：

- data_table；
- comparison_table。

如果表格属于以下类型，并且后续有问题、解答或推导，则必须配套 example_box：

- 题目条件表；
- 现金流矩阵；
- 计算数据表；
- 套利收益表；
- 收益率表；
- 贴现表；
- 价格比较表；
- 公允价值计算表。

推荐组合：

- data_table 承载已知条件和数值矩阵；
- formula_card 承载核心公式；
- example_box 承载问题、步骤、计算结果和复习启示。

不要把所有表格都强行改成 example_box。单纯分类表、背景表、链接表、市场材料表，不需要生成例题卡。

## 8. 图表型 visualBlock 生成规则

生成 line_chart、curve_chart、payoff_chart 前必须确认有可绘制数据点。

必须遵守：

- 不允许生成没有数据点的 line_chart / curve_chart / payoff_chart；
- 没有真实数据点时，可以使用概念点，但必须明确说明“概念示意，不是历史时间序列”或同等含义；
- 概念点只能表达方向、相对高低、曲线形状或盈亏结构，不能伪装成真实市场数据；
- 如果无法可靠给出真实点或概念点，应使用 chart_explanation；
- 如果前端图表类型要求数值型 x 轴，不要使用无法解析的文字 x 值；应改用数值阶段，并在 description 或 keyTakeaways 中解释阶段含义。
- 禁止生成只有坐标轴、标题、说明和关键结论，但没有曲线或数据线的空白图。
- 每章增强后必须检查所有图表型 visualBlocks 是否能实际渲染，包括 line_chart、curve_chart、payoff_chart。
- 检查时必须确认 `points` / `series` / `curves` 字段符合 VisualBlockRenderer 期望结构。

空白图表属于内容生成错误。图表只显示坐标轴、边框和结论，但没有曲线时，必须回到 JSON 检查 points / series / curves 是否符合渲染器期望结构。

## 9. 每章增强前必须产出

每章增强前必须产出或更新：

- slide inventory：逐页清点 PPT/PDF 内容；
- priority map：按 P0/P1/P2/P3 做复习价值分层；
- example / application / derivation audit：审计例题、应用题、连续页推导链；
- enhancement plan：说明计划新增或重排的模块、知识点、公式、例题和 visualBlocks。

这些文件不是形式化清单，而是防止生成阶段过度概括、误删例题、误把拓展材料放入主路径的工作依据。

## 10. 每章增强后必须产出

每章增强后必须产出或更新：

- priority review：记录最终哪些内容进入主路径，哪些被降权或移入拓展；
- 增强前后统计：nodes、formulas、examples、cases、visualBlocks 及类型分布；
- validate / lint / build 结果；
- 预览路径；
- 无法确认的数据、图片、公式或案例细节。
- 所有图表型 visualBlocks 的可渲染检查结果。

如果发现原计划中有误判，必须同步修正 audit 文件，不能让旧的错误判断留在文档里。

## 11. 禁止事项

生成和增强时禁止：

- 把所有 PPT 内容等权展示；
- 把新闻链接、截图、市场背景放到核心路径前面；
- 为了完整硬塞 visualBlocks；
- 因为公式对象抽取不完整就删除例题；
- 因为数值暂时不确定就删除题目结构；
- 伪造 PPT 中不存在的数据、权重、案例或结论；
- 把完整应用题降级成普通表格；
- 把连续页推导拆散成零散说明；
- 把核心例题降为 P2/P3；
- 用公式卡或数据表替代完整 example_box；
- 写入 `imes`、裸 `approx`、`(N_A)` 这类损坏公式或伪公式；
- 生成没有数据点或数据结构不匹配的空白曲线图；
- 修改 schema 或页面代码来掩盖内容生成不足。

最终目标是让课程页面成为“期末复习路径”：

- 学生能清楚看到哪些必须掌握；
- 哪些重点理解；
- 哪些只是辅助；
- 哪些属于拓展；
- 每个核心例题都能看到条件、问题、解法、结果和复习启示。
