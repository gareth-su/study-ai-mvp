# ysjrgj ch01/ch02/ch04 Generation Lessons

审查日期：2026-05-14
适用对象：后续 ch03 / ch05 / ch07 生成与增强

## 1. 导论章不能扩成百科

- 问题模式：为了显得完整，把监管史、市场制度、复杂定价和外部案例大量塞入导论章。
- 为什么影响学习质量：学生还没有掌握后续计算工具时，过多细节会遮蔽“衍生品是什么、谁使用、为什么定价靠无套利”的主线。
- 后续生成如何避免：导论章只建立词汇表和直觉；公式只保留 P0 直觉公式，复杂推导留到专题章。
- 可执行检查口令：导论章每个扩展段落都问“它是在建立后续词汇，还是在提前讲专题章？”后者删减或降级。

## 2. 机制章必须讲流程，不只列名词

- 问题模式：机制章堆出合约条款、保证金、清算所、交割等名词，但没有说明交易从开仓到退出如何流动。
- 为什么影响学习质量：学生会记住术语，却无法解释一笔交易如何产生盈亏、何时追加保证金、清算所何时介入。
- 后续生成如何避免：每个机制章至少有一个主流程 visualBlock，并让正文按流程顺序解释。
- 可执行检查口令：能否用“先…再…然后…最后…”复述本章核心机制？不能则重排结构。

## 3. 计算章必须同步处理正文、公式、例题、图表和 metadata

- 问题模式：正文讲连续复利，公式卡用离散口径；例题参数与表格不同但未说明；图表有点位但缺解释。
- 为什么影响学习质量：计算章最怕多套口径并存，学生会照公式算出数却不知道适用条件和参数来源。
- 后续生成如何避免：每个 P0/P1 公式同时检查 usage、pitfalls、例题参数、图表说明和表格 metadata。
- 可执行检查口令：对每个公式问“正文有没有引入？例题有没有使用？图表/表格有没有同口径说明？metadata 有没有总结？”

## 4. 成组概念不得缺半边

- 问题模式：只讲多头不讲空头，只讲初始保证金不讲维持保证金，只讲收固定不讲付固定，只讲即期利率不讲远期利率。
- 为什么影响学习质量：衍生品和利率概念多为成对或成组三元关系，缺半边会导致方向判断错误。
- 后续生成如何避免：生成前列出成组概念清单，生成后逐项核对正文和 visualBlock 是否同时覆盖。
- 可执行检查口令：搜索每组概念的全部关键词；少一个就补，不允许只在表格中出现而正文不解释。

## 5. 公式必须有适用条件

- 问题模式：公式卡只有公式和变量，没有说明复利口径、现金流时点、资产是否有收益、是否含期权、是否平坦曲线等条件。
- 为什么影响学习质量：金融公式的错误通常不是代数错，而是把公式用到不适用的场景。
- 后续生成如何避免：formula_card 必须有 priority、usage、pitfalls；usage 写“何时用”，pitfalls 写“何时不能用/易错方向”。
- 可执行检查口令：每张 formula_card 至少回答“适用对象、时间口径、利率口径、方向符号、不能用场景”。

## 6. example_box 必须说明来源和参数关系

- 问题模式：例题没有 sourceType/sourceNote，或例题参数与公式卡、chart、table 不一致但未说明。
- 为什么影响学习质量：学生会误以为不同 visualBlock 是同一题，导致参数混算。
- 后续生成如何避免：每个 example_box 均写 sourceType/sourceNote；若与相邻图表或另一例题参数不同，显式说明“不共用同一组参数”。
- 可执行检查口令：检查所有 example_box：sourceType/sourceNote 是否存在？参数是否能与公式和图表一一对应？不能对应是否显式脱钩？

## 7. chart/table metadata 必须与正文一致

- 问题模式：chart points 正确但缺 description/keyTakeaways；table 有数据但不解释为什么重要。
- 为什么影响学习质量：网页呈现时学生只看到图表，不一定知道它与正文哪一段对应。
- 后续生成如何避免：comparison_table、data_table、line_chart、curve_chart 必须补 description 和 keyTakeaways，并用正文同一口径。
- 可执行检查口令：每个图表独立截出来看，是否能仅凭 title/description/keyTakeaways 看懂教学目的？不能则补 metadata。

## 8. JSON/LaTeX 必须同时合法

- 问题模式：LaTeX 本身正确但 JSON 反斜杠未转义，或 JSON 合法但 KaTeX 无法渲染。
- 为什么影响学习质量：内容校验可能通过部分字段，但网页公式渲染失败会直接破坏学习体验。
- 后续生成如何避免：所有 formula 和 formulaLatex 同时做 JSON parse 与 KaTeX render 检查，特别关注 `\frac`、`\text`、`e^{-rT}`、`\Delta`、`\&`。
- 可执行检查口令：运行“JSON parse + KaTeX render all formula/formulaLatex”，任何失败都先修公式，不继续审稿。

## 9. PPT 图示未接入时必须说明结构化替代理由

- 问题模式：PPT 中流程图、收益图、表格没有原样接入，也没有说明被哪个 visualBlock 替代。
- 为什么影响学习质量：PPT 的 P0/P1 图示通常承担核心教学功能，遗漏会让课程内容断链。
- 后续生成如何避免：对每张 P0/P1 PPT 图示建立映射：原图示 → process_flow / chart / table / concept_map / example_box；若压缩或排除，说明理由。
- 可执行检查口令：列出 PPT P0/P1 图示、表格、公式、例题链；每项必须有“已接入/结构化替代/合理排除”的状态。

## 10. 不要暴露工程词

- 问题模式：正文或 visualBlock 中出现 source、chunk、generated、JSON、node id、fallback、filePath 等工程词。
- 为什么影响学习质量：工程词会打破课程语境，让学生误以为内容是生成管线残留而不是教材。
- 后续生成如何避免：最终内容只保留教学术语；来源说明使用“PPT例题/标准化复习例题”等面向学习者的表达。
- 可执行检查口令：全章 grep 工程词；除 audit 文件外，用户可见 JSON 内容不得出现工程残留。
